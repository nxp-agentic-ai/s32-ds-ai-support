# JSON patch schema and per-driver recipes

Structured `modifications` delta accepted by the skill. Apply in the
order shown; later steps override earlier ones.

## Top-level shape

```jsonc
{
  "tools": {
    "DCD":  { "enabled": true },
    "IVT":  { "enabled": true },
    "GTM":  { "enabled": false }
  },
  "peripherals": {
    "add":    [ { "type_id": "Wdg_43_Instance1", "mode": "autosar", "name": "Wdg" } ],
    "remove": [ "Lin_43_LPUART_FLEXIO" ],
    "patch":  [
      { "name": "Mcu",
        "sets": { "McuGeneralConfiguration.McuTimeout": "100000",
                  "McuGeneralConfiguration.McuNoPll": "false" } }
    ]
  },
  "pins":   { /* pin-routing patches (see Pins tool schema in the .mex) */ },
  "clocks": { /* clock-tree patches (see Clocks tool schema in the .mex) */ },
  "common": {
    "description": "Custom starter mex generated by s32ct-generate-mex-config"
  }
}
```

Unknown top-level keys are an explicit error, not silently ignored.

## Application order

1. `common` patches (description, top-level metadata).
2. `tools` enable/disable flags on top-level tool sections.
3. `peripherals.remove` - drop matching `<instance name="...">` blocks.
4. `peripherals.add` - insert new `<instance>` blocks (resolve
   `type_id` against the installed RTD; use `s32ct-peripherals-info` to
   enumerate the catalogue).
5. `peripherals.patch` - apply `<set id="...">value</set>` overrides
   on named instances; create missing `<set>` nodes when needed.
6. `pins` / `clocks` - structured patches to those tool sections.

## `peripherals.add` - `type_id` resolution

Valid `type_id` values are RTD-specific and live inside the installed
MCU-data package. Discover them via `s32ct-peripherals-info`, which
inspects
`<S32DS_INSTALL>/eclipse/mcu_data/components/<platform_sdk>/<driver_folder>/<driver_folder>.component`.
This skill validates that a `type_id` is well-formed but does not
enumerate the catalogue itself.

## Recipe: plain clone

Byte-clone of the template with a fresh top-level UUID; sidecar
propagated:

```jsonc
{ "output_path": "C:\\tmp\\S32K312_starter.mex" }
```

## Recipe: enable DCD + IVT for boot-image work

> **Caution - `"overwrite": true` destroys data.** Any existing file at
> `output_path` is irreversibly replaced, with no prompt and no backup.
> Confirm the resolved `output_path` with the user and back up or commit
> the existing `.mex` before enabling it. Omit the flag (it defaults to
> `false`) so the run fails safely when the destination already exists.

```jsonc
{
  "output_path": "C:\\tmp\\S32K312_boot.mex",
  "overwrite": true,
  "modifications": {
    "tools":  { "DCD": { "enabled": true }, "IVT": { "enabled": true } },
    "common": { "description": "S32K312 boot-image scaffold" }
  }
}
```

## Recipe: tweak `Mcu` defaults and drop LIN

```jsonc
{
  "output_path": "C:\\tmp\\S32K312_no_lin.mex",
  "modifications": {
    "peripherals": {
      "remove": ["Lin_43_LPUART_FLEXIO"],
      "patch": [{
        "name": "Mcu",
        "sets": {
          "McuGeneralConfiguration.McuTimeout": "100000",
          "McuGeneralConfiguration.McuInitClock": "false"
        }
      }]
    }
  },
  "validate": true
}
```

## Recipe: add a watchdog instance

```jsonc
{
  "output_path": "C:\\tmp\\S32K312_with_wdg.mex",
  "modifications": {
    "peripherals": {
      "add": [{ "type_id": "Wdg_43_Instance1", "mode": "autosar", "name": "Wdg" }]
    }
  }
}
```

## Error responses

| Condition | Message template |
|---|---|
| Template missing | `No reference template found at '<dir>\<mcu>_default.mex'. Bundled: <list>.` |
| Explicit `template_path` missing | `Reference template '<path>' not found.` |
| Package / mcu_data mismatch | `Requested package/mcu_data does not match template (template=<...>).` |
| `output_path` exists, `overwrite=false` | `Output '<path>' already exists. Re-run with overwrite=true.` |
| Template not valid XML | `Reference template '<path>' is not valid XML: <parser error>.` |
| Unknown modification key | `Unsupported modification key '<key>'. Allowed: tools, peripherals, pins, clocks, common.` |
| `peripherals.patch` on missing instance | `Instance '<name>' is not present. Available: <list>.` |
| `peripherals.add` unknown `type_id` | `Unknown type_id '<id>' for mcu_data='<sdk>'. Verify via s32ct-peripherals-info.` |
| Validation reports problems | `Generated '<path>' but validation reported <N> problem(s). <captured text>` |

Errors surface as actionable text; the skill does not raise raw
exceptions.
